# Project App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Odoo-style Project app (projects, per-project stages, tasks on a stage kanban, subtasks, dependencies, milestones, timesheets) with members-only projects enforced on the server.

**Architecture:** A new ORM capability, the per-request **row scope**, ANDs a module-supplied SQL condition into every generic CRUD read/update/delete and backs `orm.CanSeeRecord` for the record-anchored services. `core/modules/project` (`type: go`) registers its tables on the generic surface with that scope. Postgres triggers keep the stored aggregates (`spent_hours`, `blocked`, counts) consistent, and Go middleware and overrides enforce the write invariants. The frontend engine's kanban learns to build its columns from many2one records.

**Tech Stack:** Go (Echo, pgx, custom ORM `core/orm`), PostgreSQL 18 (plpgsql triggers), Next.js + TypeScript (`@eerp/core-front` engine, MUI), vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-project-design.md` (read it first, since it holds every behavior rule this plan implements).

## Global Constraints

- Every rule in the spec's "Decisions" section is a requirement. "Odoo behavior" fills any gap.
- Non-visible row = **404**, never 403. A manager-only write by a non-manager who *can* see the project = **403**. A bad reference = **422** `VALIDATION_ERROR`. A refused delete = **409**.
- Row-scoped tables are **never** served from the Redis read cache.
- Admin = caller's groups contain `project_admin` **or** `PermissionRepository.Has(ctx, identity.Roles, "project:project:admin")` (a role holding `*:*:*` satisfies it).
- Default stages for a new project: `New` (sequence 10), `In progress` (20), `Done` (30, `closed = true`).
- Use `rg` never `grep`. `depguard`: no `fmt`/`log`, use `common.Logger`. Commit format `<type>(scope): <description>` ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Use `git -c user.name=noiia -c user.email=edwin.lecomte31@gmail.com commit`.
- Go DB tests use `core/internal/testdb.Open(t)` + `testdb.MigrateModules(t, app, "auth", ..., "project")`, under a fresh `uuid.New()` tenant, and clean only their own rows.
- Coverage floors (`make test`) must hold: core 85 %, frontend shell/engine 80 %. Never lower a threshold.
- After code changes run `graphify update .`.
- Every user-visible label gets a msgid in `core/modules/project/i18n/project.pot` and a French translation in `fr.po`.

## Review Focus

1. **Membership revoked or project made private**: the next request from the ex-member 404s on the project, its tasks, timesheets, chatter (test in Task 3 `TestRowScope_RevokedMemberLosesAccessImmediately`).
2. **A blocker is deleted (soft) or its dependency row removed**: dependents' `blocked` turns false (test in Task 3 `TestTriggers_BlockedClearsOnBlockerDelete`).
3. **Timesheet hours ≤ 0, or a date missing**: 422, nothing stored (test in Task 4 `TestTimesheet_RejectsNonPositiveHours`).
4. **A project whose stages were all deleted**: tasks with `stage_id` null still show in the kanban's "No stage" column and nothing is lost (Task 5 test `keeps stage-less cards in the No status column`).
5. **Soft-deleted rows in aggregates**: a soft-deleted timesheet or subtask stops counting in `spent_hours` / `subtask_hours` / counts (test in Task 3 `TestTriggers_SoftDeleteExcludedFromAggregates`).

**Interfaces:**
- Produces: `type RowScopeFunc func(ctx context.Context) (cond query.Condition, ok bool, err error)`. `ok=false` means "no restriction" (e.g. admin), and `err` means fail closed (the generic layer returns 500).
- Produces: `orm.WithRowScope(fn orm.RowScopeFunc) orm.Option`.
- Produces: `orm.CanSeeRecord(ctx context.Context, db *orm.DB, table string, id uuid.UUID) (bool, error)`. It returns true when the table has no row scope or is unregistered (preserving today's behavior for every other table), and otherwise `EXISTS(SELECT 1 FROM <table> WHERE id=$1 AND deleted_at IS NULL AND tenant AND <scope>)`.
- The condition's `$n` placeholders are renumbered like every other `query.Condition` (follow how `tenantCondition`/`publicConditions` conditions are appended).

**Interfaces:**
- Consumes: scopes, `IsAdmin`, `orm.CanSeeRecord` (Tasks 1, 3).
- Produces: Echo middlewares `ValidateProjectBody`, `ValidateStageBody`, `ValidateMemberBody`, `ValidateTaskBody`, `ValidateMilestoneBody`, `ValidateDependencyBody`, `ValidateTaskLinkBody` (task_user/task_tag), `ValidateTimesheetBody`, and on `*Handler` (built with `NewHandler(db *orm.DB, perms *auth.PermissionRepository)`): `DeleteProject`, `DeleteStage`, `UpdateTask(get echo.HandlerFunc) echo.HandlerFunc` (project change path, else falls through to the generic update), `CanManage` mounted at `GET /api/v1/project/:id/can_manage` → `{"can_manage": bool}` (404 if invisible; confirm the derived permission is a read the frontend user holds, and if not, mount it JWT-only).

Rules (each one is a test row in a table-driven `TestValidate_*`):
- Any `*_id` reference (project, stage, milestone, parent, task, depends_on) must be visible (`CanSeeRecord`), else 422. stage/milestone/parent/task must belong to the record's `project_id`, else 422. A dependency may cross projects. Denormalized `project_id` on child rows is **set by the middleware** from the parent task (the client value is overwritten).
- A task's `stage_id` absent on create gives the project's lowest-sequence stage.
- `parent_id` cycle → 422. Dependency cycle (`depends_on` reaches `task_id`) → 422. Self-reference → 422. Use a recursive CTE.
- Writes to `project` (PUT), `project_member`, `project_stage` (all verbs) are allowed only for the manager or an admin, else 403 (404 if invisible). Anyone with `project:project:write` may create a project. The creator becomes `manager_id` if none is given.
- Timesheet: `user_id` defaults to the caller. A different user, or editing/deleting someone else's line, requires manager/admin, else 403. `hours > 0` and `date` required, else 422.
- Milestone `reached` false→true stamps `reached_at = now()`, and true→false clears it.
- `DeleteProject`: live tasks → 409 (`{"error":{"code":"CONFLICT",...}}` same shape as event's). Otherwise, one `orm.Transact` soft-deletes stages, milestones, members, then the project.
- `DeleteStage`: live tasks in it → 409.
- `UpdateTask` with a changed `project_id`: a subtask → 422. Otherwise, in one transaction, move the task and its descendants. Each moved task gets `stage_id` remapped by name in the target project, else the target's first stage, and `milestone_id = NULL`. Timesheets/task_user/task_tag/dependency rows (where `task_id` is a moved task) get the new `project_id`. The caller must see the target project (else 422). Then return via the generic `GetByID`.

**Interfaces (exact):**
```ts
// view-fields.ts
export interface KanbanColumnsConfig {
  orderField: string      // e.g. 'sequence'
  labelField: string      // e.g. 'name'
  foldField?: string      // e.g. 'closed', truthy → column collapsed
  scopeField?: string     // e.g. 'project_id' — same column name on the card entity AND the column entity
  canEdit?: string        // name registered with registerKanbanColumnsGuard
}
export interface ViewModeDefaults { /* existing */ kanbanColumns?: KanbanColumnsConfig; kanbanBadgeField?: string }
// kanban-columns.ts
export function registerKanbanColumnsGuard(name: string, fn: (scopeId: string) => Promise<boolean>): void
```
Behavior:
- When the status field's descriptor is `type: 'relation'`, `relation.kind: 'many2one'` **and** `kanbanColumns` is set, columns are records of `relation.entity` loaded through `relationOps.listPage` (`order=<orderField>`, `filter[<scopeField>]=<id>` when the list's filter pins `scopeField` to one id). Column key = record id, title = `labelField`. Fold → collapsed column (header + count, expandable on click). Plus the existing `NO_STATUS` column. The selection path stays unchanged.
- Unscoped (no single scope id pinned): load all visible column records and merge by label, ordered by min `orderField`. A merged column's server query is `in[<status>]=<ids>`. Dropping a card into a merged column picks the id whose `scopeField` equals the card's own `scopeField`. If there's none, the move is refused with the translated error "This project has no stage named {name}." and the card reverts.
- Scoped + `canEdit` guard resolves true: show "Add column" (creates `{labelField: name, orderField: max+10, scopeField: id}`), inline rename (PUT label), and drag-reorder of column headers (PUT `orderField` 10, 20, … for the new order). Hide all three otherwise.
- `kanbanBadgeField` (a boolean field): a card whose value is true shows a small error-colored `Chip` labeled with that field's label (translated).
