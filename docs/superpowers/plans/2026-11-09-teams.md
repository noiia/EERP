# Teams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Teams app: a team dashboard, full-screen team chat (channels and direct messages, with attachments, mentions, unread counts and reactions), per-team roles, and a team file manager with per-person sharing.

**Architecture:** The Go package `core/internal/teams` holds models, repositories and handlers. They are mounted JWT-only under `/api/v1/teams` and gated on the `teams` module being active. Live chat frames ride the existing presence WebSocket (`presence.Hub.SendToUsers`). Mentions go through `internal/notify`, and file bytes through `pictures.ObjectStore`. The frontend pages are hand-built under `core-front/apps/shell/app/app/teams/` and call Go through one catch-all BFF proxy route, `/api/teams/[...path]`.

**Tech Stack:** Go (echo v5, core/orm, gorilla/websocket hub), Next.js App Router, MUI, zustand, vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-teams-design.md`

## Global Constraints

- Roles are exactly `owner|member|guest`. A non-member of a team gets **404**, never 403, so a team's existence doesn't leak.
- Every query is pinned to `identity.TenantID`. Identity comes from `auth.MustIdentity(ctx)`.
- Tables stay off the generic CRUD surface: `orm.Register[T](orm.WithTableName(...), orm.WithExcluded())`.
- Unique indexes are hand-written in the module's `Migrate()`, never derived from struct tags.
- Message body ≤ 4000 characters. A reaction emoji is ≤ 16 bytes. Names (team, channel, folder, file) are 1–200 characters after trim.
- Error JSON uses the house shape `{"error":{"code","message","request_id"}}` (copy `errorJSON` from `internal/chatter/handler.go`).
- Live frames are sent with `Hub.SendToUsers` only, never `Broadcast`.
- Logging goes through `common.Logger` (zap). `fmt`/`log` are blocked by depguard, except `fmt.Errorf`.
- Search with `rg`, never `grep`. Prefix shell commands with `rtk`.
- Before every push: `make test` green, and coverage floors per CLAUDE.md (core ≥ 85%, frontend packages ≥ 80% on each metric).
- Every user-visible string goes through `<T text=…>` / msgids in `core/modules/teams/i18n/teams.pot` and `fr.po`.

## Review Focus

1. **Guest posts a message or uploads a file**: expect 403 `FORBIDDEN`, and nothing written. Tests in Tasks 3 and 4.
2. **Removing or demoting the last owner**: expect 409 `LAST_OWNER`, and the team keeps one owner. Test in Task 2.
3. **A user mentions someone outside the channel**: expect no notification sent to that id. Test in Task 3.
4. **Moving a folder into its own subtree**: expect 422 `VALIDATION_ERROR`, never a cycle. Test in Task 4.
5. **Opening a direct conversation with yourself, or twice with the same person**: expect 422 for yourself, and the same channel id returned both times. Tests in Task 3.

### Task 3: Chat: direct conversations, messages, unread, reactions, live, mentions

**Files:**
- Create: `core/internal/teams/chat_handler.go`, `core/internal/teams/chat_handler_test.go`, `core/internal/teams/category.go`

**Interfaces:**
- `func (h *Handler) channelAccess(c *echo.Context, channel uuid.UUID) (Channel, string /*role*/, []uuid.UUID /*audience*/, error)`:
  - For a team channel, the role comes from team membership and the audience is all team members.
  - For a direct conversation, the role is `member` for its 2 participants and the audience is those two.
  - Anyone else gets 404.
- Routes: `GET|POST /direct`, `GET|POST /channels/:channel/messages`, `POST /channels/:channel/read`, `POST /messages/:message/reactions`, `GET /attachments/:id`.
- Message wire shape: `{id, channel_id, author_id, author_name, body, created_at, attachments:[{id,filename,mime,size}], reactions:[{emoji,count,mine}]}`. A GET returns `{data:[…]}` newest-first. `?before=<RFC3339>` and `limit` (default 50, max 100).
- Live frames, with `json` tags exactly:
  - `{type:"chat_message", channel_id, team_id|null, message:<wire>}`
  - `{type:"chat_reaction", channel_id, message_id, reactions:[…]}`. `mine` is omitted in the frame. The client computes it from its own toggle.
- POST message accepts JSON `{body, mentions: [uuid]}` or multipart (`body`, repeated `mentions`, repeated `files`). Multipart without S3 returns 503 `STORAGE_UNAVAILABLE`. Empty body and no file returns 422. Write requires `CanWrite`.
- Mentions: ids filtered to the channel audience, minus the author. Each gets `notifier.Personal(ctx, tenant, id, notify.Message{Category:"teams", Title:"<author> mentioned you", Body: first 140 characters, Link:…})`. The link is `/teams/<team>/channels/<channel>` or `/teams/direct/<channel>`. A notify error is logged, never failing the post.
- `category.go`: `func init() { notify.RegisterCategory(notify.Category{Key: "teams", Label: "Teams"}) }`.
- POST `/direct {user_id}`:
  - Target is yourself → 422.
  - Target is not a staff user of the tenant → 422.
  - Otherwise get or create by `DirectKey`, inside a transaction with the unique index as the guard (on 23505, re-read). It creates both `chat_channel_member` rows.
  - GET `/direct` returns `{data:[{id, other_user:{id,display_name,email}, unread, last_message_at}]}`.
- Unread: `Repository.UnreadCounts(ctx, tenant, user uuid.UUID, channels []uuid.UUID) (map[uuid.UUID]int, error)`, one SQL query: `count(*) FILTER (WHERE m.author_id <> $user AND (cm.last_read_at IS NULL OR m.created_at > cm.last_read_at))`, LEFT JOIN on the caller's cursor row. Filled into the channel list, the direct list, and `TeamSummary.Unread` (the sum over the team's channels).
- POST `/read` upserts the cursor to `now()` (`orm.Repository.Upsert` on `(channel_id, user_id)`). Guests may mark as read.
- Reaction toggle requires `CanWrite`. It deletes the row if it exists, otherwise inserts it, then pushes the frame with fresh counts.
