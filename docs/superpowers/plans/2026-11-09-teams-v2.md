# Teams v2 + LDAP Photos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LDAP photos become ERP avatars, and Teams gains per-user sidebar order, private conversations with per-team groups, linked folders shown in a right panel, files sent into folders, inline images, and a breadcrumb that resets.

**Architecture:**
- **LDAP photo sync** lives in `internal/auth/providers` (a `PhotoSyncer` called after provisioning). It reuses `internal/pictures` (repository + `ObjectStore`) on the `(users, id, avatar)` anchor. A JWT-only avatar route serves the photos.
- **Teams access rules** are all funnelled through two Go functions in `core/internal/teams`: `canSeeChannel` and `folderVisible`. Every existing route calls them.
- **Frontend changes** stay in `apps/shell/src/teams`, the engine's `AvatarWithPresence`, and the breadcrumb store.

**Tech Stack:** Go (echo v5, core/orm, go-ldap), Next.js App Router, MUI, zustand, vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-teams-v2-design.md` (v1 context: `docs/superpowers/specs/2026-11-09-teams-design.md`, `docs/adr/ADR-037-teams.md`)

## Global Constraints

- **Visibility rule (one function, used everywhere):** `canSeeChannel` = team owner, OR the channel's access list is empty, OR the user is listed directly or through a team group. Invisible or unknown → **404**, never 403.
- **Restricted folders:** a folder is restricted when it, or any ancestor, is linked (`chat_channel.folder_id`) to a channel whose access list is non-empty. A restricted folder and its files are visible only to users who `canSeeChannel` that channel. An explicit `team_file_share` to a user still allows that user to download the file.
- **One conversation per folder:** a folder is linked to at most one channel (unique live index on `chat_channel.folder_id`). Only team channels (`team_id` not null) can link a folder.
- **Inline images:** `image/jpeg`, `image/png`, `image/gif`, `image/webp`. Thumbnail max about 320×240 px. SVG is never inline.
- **LDAP photo:**
  - Accepted only as JPEG or PNG, at most 2 MB (larger is ignored and logged).
  - Replaced only when the sha256 of the bytes changed.
  - Cleared when the directory has none.
  - Any sync error is logged and never fails the sign-in.
  - Nothing syncs without S3.
- **Avatar route:** `GET /api/v1/avatars/:user` is JWT only, same tenant, staff users only, `Cache-Control: private, max-age=300`, and returns 404 when there is no avatar.
- **Auto-created folder:** named exactly after the conversation, at the team root, created in the same transaction as the message; a name taken at the root gets `"<name> (2)"`, `"(3)"`… `created_by` = the sender.
- Every query is pinned to the tenant. Error JSON uses the house shape `{"error":{"code","message","request_id"}}`. Live frames are sent with `Hub.SendToUsers` only.
- Every user-visible string goes through `<T>`/`t()` with literal msgids. Add them to `core/modules/teams/i18n/{teams.pot,fr.po}`, or to `apps/shell/i18n/` for strings outside Teams (auth settings, account menu).
- Before every push, `make test` must be green with the coverage floors (Go ≥ 85%, currently 85.3%, so new Go code ships with tests; frontend ≥ 80% on each metric). Never lower a threshold.
- Environment facts: `.superpowers/sdd/<plan>/common-context.md` (Go PATH, CONFIG, pnpm via npx, git identity, rg not grep).

## Review Focus

1. **An unlisted team member probing a private channel by id**: messages, read, reactions, attachment download, `/files/:file/download` for files of its folder, the folder listing, and the Shares view. Expect 404 everywhere. Test in Tasks 3 and 4.
2. **A user removed from the team, or from a group, while a private channel is open**: they no longer receive its live frames, mentions or unread counts. Test in Task 3.
3. **Moving a file or folder into a restricted folder by someone who can't see it**: expect 404/422 and no move. A visible user moving a restricted folder out of its subtree: allowed only when they can see the destination. Test in Task 4.
4. **Two files sent at once into a conversation with no folder**: expect exactly one auto-created folder, linked once, with no duplicate `general (2)`. Test in Task 4.
5. **An LDAP sign-in when S3 is down or the photo is oversize**: the sign-in still succeeds and the avatar is unchanged. Test in Task 1.

- Deleting a folder (`DeleteFolderTree`) sets `folder_id = NULL` on channels linked to any folder of the subtree. Deleting a channel leaves its folder in place.
- `POST /channels/:channel/messages` with files, **team channel**:
  1. In one transaction: lock the channel row (`SELECT … FOR UPDATE`) so two concurrent sends create one folder.
  2. Resolve `folder_id`; if absent, create the root folder named after the channel (with the `(2)` suffix rule) and link it.
  3. Insert a `team_file` per upload in that folder (uploaded objects are put before the transaction; on rollback, delete them).
  4. Insert `chat_message_file` rows.
  - Direct channels keep `chat_attachment`.
- Message wire `attachments[]` entries gain `kind: "attachment" | "file"`. For `"file"`, `id` = the `team_file` id, and the frontend downloads from `/files/:id/download`. A deleted file's entry is `{kind:"file", id, deleted:true}` with an empty name.
