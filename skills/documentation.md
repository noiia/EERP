# Documentation Skill

Your task is to maintain the project documentation.

The documentation follows these principles.

## Audience

The audience is software engineers.

Assume they know Go, HTTP, SQL and modern backend development.

Do not explain basic programming concepts.

---

## Goal

Documentation should explain:

- architecture
- concepts
- responsibilities
- interactions
- extension points

Avoid documenting obvious implementation details.

---

## Writing style

Write using:

- short paragraphs
- descriptive headings
- bullet lists
- diagrams when useful

Avoid marketing language.

Avoid unnecessary adjectives.

Be factual.

---

## Every page should answer

What is this?

Why does it exist?

How does it work?

How is it used?

What should contributors know?

---

## Code examples

Use realistic examples.

Keep them small.

Explain only the relevant parts.

---

## Diagrams

Prefer Mermaid.

Typical diagrams include:

- Flowcharts
- Sequence diagrams
- Class diagrams
- State diagrams

---

## Keep documentation synchronized

Whenever code changes:

- Update impacted pages.
- Update diagrams.
- Update examples.
- Remove obsolete content.
